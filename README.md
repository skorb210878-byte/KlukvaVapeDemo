# Klukva — демо Telegram Mini App (Фаза 1, эскиз)

Статический фронтенд витрины вейп-шопа и макет админки. Без сервера, без базы данных,
без реальных заказов. Все данные (корзина, заказы, правки товаров) живут в
`localStorage` браузера конкретного устройства и не передаются никуда.

## Структура

```
index.html     — витрина (Mini App)
admin.html     — макет админки
css/           — стили (вся палитра и размеры — переменные в css/style.css :root)
js/            — вся логика (ES-модули, без фреймворков и сборщика)
data/products.json — демо-товары (вымышленные, 3 категории)
assets/app-cover.png  — обложка 640×360 для /newapp в BotFather
assets/app-avatar.png — аватарка бота 512×512 для /setuserpic (создаётся скриптом)
assets/photos/products/ — сюда кладутся фото товаров (см. раздел 2)
scripts/make_covers.py     — генерирует app-cover.png и app-avatar.png из одной фотографии
scripts/optimize_images.py — сжимает фото товаров и делает превью для каталога
screenshots/   — снимки ключевых экранов
```

## Внешний вид

Фирменная тёмно-фиолетовая палитра задана один раз в `css/style.css` (блок `:root`) —
там же радиусы, размеры тач-целей и пропорции фото. Чтобы перекрасить или изменить
размеры — правьте только эти переменные, остальной CSS и JS их переиспользуют. Под тему
Telegram/системы палитра не подстраивается: наоборот, `js/tg.js` передаёт эти же цвета
в Telegram через `setHeaderColor`/`setBackgroundColor`/`setBottomBarColor` (с проверкой
версии Bot API), чтобы шапка и фон внутри Telegram совпадали с приложением.

## 1. Запуск локально

Открыть `index.html` напрямую двойным кликом **не получится** — браузер блокирует
`fetch('data/products.json')` для страниц, открытых по `file://`. Нужен любой локальный
статический сервер из корня проекта, например:

```powershell
# если установлен Python
python -m http.server 8080

# если установлен Node.js
npx serve .
```

Затем открыть в браузере:
- витрина — http://localhost:8080/index.html
- админка — http://localhost:8080/admin.html

Проверено в Chrome (desktop headless, мобильный вьюпорт 390×844, светлая и тёмная тема).

## 2. Фото

Все фото — опциональны: без них показывается аккуратная фиолетовая заглушка с иконкой
категории, ничего не ломается.

### 2.1. Обложка и аватарка бота

1. Установить Pillow (один раз): `pip install pillow`
2. Положить фотографию по пути `assets/photos/app.jpg`
3. Запустить:
   ```powershell
   python scripts/make_covers.py
   ```
4. Получится `assets/app-cover.png` (640×360, для `/newapp` в BotFather) и
   `assets/app-avatar.png` (512×512, для `/setuserpic`). Обрезка — по центру; если
   главный объект на фото съехал к краю, смотрите подсказку в выводе скрипта
   (флаги `--focus-x`/`--focus-y`) или подрежьте исходник заранее.

### 2.2. Баннер на главной (пока выключен)

В `js/config.js` есть блок `banner: { enabled, image, height }`. Сейчас `enabled: false` —
баннер не показывается. Чтобы включить: положить файл по пути из `banner.image`
(по умолчанию `assets/photos/banner.jpg`) и поставить `enabled: true`.

### 2.3. Фото товаров

Положить файлы в `assets/photos/products/`, имя файла = id товара (`1.jpg`, `12.jpg`, …).
Затем сжать и сделать превью:

```powershell
python scripts/optimize_images.py
```

Скрипт берёт файлы из `assets/photos/products/*.jpg|.jpeg|.png|.webp` и кладёт в
`assets/photos/products/optimized/`: полную версию (длинная сторона до 900 px, для
карточки товара) и превью `*-thumb.jpg` (400 px, для плиток каталога). **Фронтенд
показывает именно файлы из `optimized/`**, поэтому после добавления или замены фото
скрипт нужно запускать заново — иначе останется заглушка.

Если для товара нет файла (ни исходного, ни оптимизированного) — покажется фиолетовая
заглушка, каталог не сломается.
Таблица id → название → ожидаемое имя файла:

## 3. Публикация на бесплатном хостинге

Подойдёт любой статический хостинг с HTTPS. Бэкенд не нужен — выкладывается вся папка
проекта как есть.

### Вариант А: Netlify (drag-and-drop, без аккаунта на GitHub)

1. Зайти на https://app.netlify.com/drop
2. Перетащить папку проекта в окно браузера
3. Netlify выдаст ссылку вида `https://<случайное-имя>.netlify.app`
4. (Опционально) в Site settings → Change site name задать более короткое имя

### Вариант Б: GitHub Pages

1. Создать **приватный** репозиторий на GitHub, запушить туда содержимое папки
2. Settings → Pages → Source: ветка `main`, папка `/root`
3. Через 1–2 минуты сайт появится по адресу `https://<username>.github.io/<repo>/`

### Вариант В: Cloudflare Pages

1. https://pages.cloudflare.com → Create a project → Direct Upload
2. Загрузить папку проекта, Build command — оставить пустым, Output directory — `/`

## 4. Бот без кода (BotFather)

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot`, придумать имя и username
2. Полученный токен сохранить (пригодится в Фазе 2, в демо не используется)
3. `/mybots` → выбрать бота → **Bot Settings → Menu Button** (или команда
   `/setmenubutton`) → указать ссылку на опубликованное демо (из шага 2)
4. Теперь кнопка меню бота (иконка рядом с полем ввода) открывает Mini App

Админку (`admin.html`) к кнопке меню бота привязывать не нужно — её смотрят отдельно,
по прямой ссылке, только вы или клиент.

## 5. Как показать клиенту

- **Внутри Telegram**: отправить клиенту ссылку на бота, он нажимает кнопку меню.
- **Без Telegram**: ссылку на `index.html` можно открыть в обычном браузере телефона —
  возрастной гейт, каталог и оформление заказа работают одинаково, вместо `MainButton`
  показывается обычная кнопка внизу экрана.

**Ссылку на демо и на бота отправляйте только клиенту лично** (в личном чате/почте), не
публикуйте в открытых каналах — каталог товаров 18+ не должен быть в публичном доступе.

## 6. Сброс демо-данных

В админке есть кнопка «Сбросить демо-данные» — очищает localStorage (корзину, заказы,
правки товаров) и возвращает демо к начальному состоянию. Полезно перед показом новому
клиенту.

## 7. Ограничения демо (Фаза 1)

Нет сервера, нет бота на aiogram, нет авторизации по `initData`, заказы никуда не
отправляются, импорт Excel не парсит реальные файлы (только пример предпросмотра).
Полная версия — отдельное ТЗ (`SPEC.md`), делается после одобрения эскиза.
