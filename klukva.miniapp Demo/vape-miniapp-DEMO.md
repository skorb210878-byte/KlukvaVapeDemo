# ТЗ, Фаза 1: визуальный прототип Mini App магазина («эскиз для клиента»)

> **Как использовать:** положи файл в корень пустой папки проекта как `DEMO.md` и напиши Claude Code:
> «Прочитай DEMO.md. Покажи короткий план и вопросы, код не пиши, пока я не отвечу.»

**Цель:** быстро показать клиенту, как магазин будет выглядеть и работать внутри Telegram. Это НЕ боевая система: без сервера, без базы данных, без реальных заказов и без обработки персональных данных. Полная версия (Фаза 2) описана в `SPEC.md` и делается после одобрения эскиза.

---

## 0. Правила работы

1. Сначала изучи папку (`ls`, `git status`), ничего не удаляй без спроса. Покажи план и вопросы, дождись ответа.
2. Работай этапами (раздел 9). После каждого: проверь в браузере (мобильный вьюпорт 390×844), коротко отчитайся, `git commit`.
3. API Telegram WebApp сверяй с официальной документацией, не по памяти. Новые методы вызывай только после проверки `isVersionAtLeast(...)`.
4. Файлы небольшие, комментарии на русском, имена в коде на английском.
5. Если что-то неясно, спроси, а не выбирай молча.

## 1. Что делаем и что НЕ делаем

**Делаем:** статический фронтенд на чистых HTML/CSS/JS (ES-модули, без фреймворков и сборщика). Демо-данные лежат в одном файле. Работает и внутри Telegram, и в обычном браузере (проверь, что без `window.Telegram` ничего не падает).

**НЕ делаем:** Python-бэкенд, SQLite, aiogram-бота, авторизацию по initData, реальную отправку заказов, загрузку файлов на сервер, настоящий импорт Excel. Всё это Фаза 2. В админке-макете эти места показываются как интерфейс-заглушка с пометкой «в полной версии».

## 3. Экраны витрины (mobile-first 360–430 px, нормально выглядит и на планшете)

1. **Возрастной гейт 18+:** «Мне есть 18 лет» / «Мне нет 18» (второе показывает экран «Доступ закрыт»). Подтверждение запоминается в `localStorage`. Магазин продаёт товары 18+, этот экран должен быть в дизайне с самого начала.
2. **Главная:** шапка (название и логотип из `config.js`), поиск, категории (горизонтальные чипсы с «Все»), переключатель «Только в наличии», сортировка, сетка из 2 колонок: фото, название, цена, бейдж «Нет в наличии». Подгрузка «Показать ещё» по 20 штук.
3. **Карточка товара:** слайдер фото (CSS `scroll-snap`, точки), название, цена, описание, наличие, выбор количества. Основное действие через `MainButton` «Добавить в корзину • 1 290 ₽».
4. **Корзина:** позиции, изменение количества, удаление, итог. `MainButton` «Оформить заказ • сумма».
5. **Оформление:** имя, телефон (маска +7), самовывоз/доставка (+адрес), комментарий, чекбокс 18+. Кнопка «Подтвердить заказ» → экран успеха «Заказ принят. Мы свяжемся с вами». **В демо ничего никуда не отправляется:** заказ сохраняется только в `localStorage`.
6. **Мои заказы:** список со статусами (Новый / В обработке / Выполнен). Сделай 2 заранее заполненных примера заказов, чтобы экран не был пустым при показе.
7. **О магазине:** реквизиты-заглушки (из `config.js`), контакты. В подвале маленькая пометка «Демо-версия».

Состояния у каждого экрана: `loading` (скелетоны), `error` (текст + «Повторить»), `empty` (понятное сообщение), `success`.

## 4. Макет админки (`admin.html`)

Мобильная вёрстка, вкладки: **Заказы / Товары / Импорт / Статистика**. Вверху пометка «Макет. В полной версии вход только по Telegram ID владельца».

- **Товары (главное «вау» для клиента):** список с поиском. Переключатель «в наличии» и правка цены прямо в строке. Изменения сохраняются в `localStorage` и **сразу видны на витрине** при её открытии: так клиент понимает, что будет сам управлять ассортиментом. Форма «Добавить товар» (название, описание, цена, категория, наличие, фото с превью через `FileReader`, сохранять уменьшенную копию до 400 px).
- **Заказы:** список заказов из `localStorage` (+ демо-заказы), детали, смена статуса кнопками.
- **Импорт:** зона «Загрузите Excel со списком товаров», описание формата столбцов (Артикул, Название, Цена, Категория, Наличие, Описание, Фото) и кнопка «Скачать шаблон». Реальный разбор файла не делаем: после выбора файла показать фиктивный предпросмотр («700 строк: 640 новых, 55 обновится, 5 с ошибками») с пометкой «пример».
- **Статистика:** день/неделя/месяц, заказы, выручка, средний чек, топ товаров, простая диаграмма на canvas/CSS без библиотек. Данные демонстрационные, с пометкой «пример данных».
- Кнопка «Сбросить демо-данные».

## 5. Дизайн

- Стиль: современный, сдержанный, «премиальный». Тёмная и светлая тема. Внутри Telegram цвета берутся из CSS-переменных `--tg-theme-*`, в браузере откат на `prefers-color-scheme`.
- **Акцентный цвет и название магазина меняются в одном месте** (`config.js` и CSS-переменная), чтобы быстро подогнать под вкус клиента на встрече.
- Шрифт системный (`system-ui`), без внешних подключений кроме `telegram-web-app.js`.
- Фото-заглушки генерируются на лету (SVG/CSS-градиенты с простой иконкой категории). Без скачивания картинок, без людей и детских мотивов.
- Демо-товары: вымышленные названия, без реальных брендов и без утверждений о пользе для здоровья.
- Safe area: `env(safe-area-inset-*)`. Тач-цели ≥ 44 px. Контраст не ниже WCAG AA.
- Анимации сдержанные; уважать `prefers-reduced-motion`. `HapticFeedback` на добавление в корзину и успех.
- В обычном браузере, где нет Telegram `MainButton`, показывать эквивалент: фиксированную нижнюю кнопку.

## 6. Интеграция с Telegram

`tg.js` вызывает `ready()`, `expand()`, слушает `themeChanged`, управляет `BackButton` (показывать, когда есть куда вернуться; закрывать модалки; работает на каждом экране) и `MainButton`. Все вызовы через защитную обёртку (`window.Telegram?.WebApp`), чтобы страница работала и вне Telegram. Не делай автофокус на поиск на телефоне: клавиатура закроет каталог.

## 7. Подготовка к Фазе 2

Весь доступ к данным (`getCategories`, `getProducts({q, categoryId, inStock, sort, offset, limit})`, `getProduct`, `createOrder`, `getMyOrders` и др.) только через `store.js`, остальной код не читает `localStorage` и `products.json` напрямую. Тогда в полной версии заменится одна прослойка на запросы к API, а экраны останутся прежними. Формат `products.json`: `id, sku, name, description, price (целые рубли), category, in_stock, photos[]`.

Поиск регистронезависимый для кириллицы (`toLocaleLowerCase('ru')`).

## 8. Публикация демо и показ клиенту

Описать в `README.md`:
1. Бесплатный статический хостинг с HTTPS (GitHub Pages, Netlify или Cloudflare Pages). Бэкенд не нужен.
2. Бот без кода: в BotFather `/newbot`, затем `/setmenubutton` (или Bot Settings → Menu Button) и указать URL демо. Кнопка меню бота откроет Mini App.
3. Ссылку на демо и бота отправляй только клиенту, не публикуй открыто: каталог такого товара не должен висеть в публичном доступе.
4. Как открыть демо без Telegram, прямо в браузере телефона.

## 9. Этапы

1. Каркас, `config.js`, `store.js`, данные, `tg.js`, роутер, темы.
2. Возрастной гейт, главная (поиск, категории, сортировка), скелетоны и состояния.
3. Карточка товара со слайдером, корзина.
4. Оформление, экран успеха, «Мои заказы» с примерами.
5. Админка-макет: товары (inline-правка → видна на витрине), заказы.
6. Импорт и статистика (макеты), сброс демо-данных.
7. Полировка: доступность, reduced motion, safe area, README, скриншоты.

## 10. Критерии готовности

- [ ] Открывается в Telegram (iOS/Android) и в браузере; тема Telegram подхватывается; кнопка «Назад» работает на каждом экране.
- [ ] Сценарий проходит без ошибок в консоли: 18+ → каталог → поиск → карточка → корзина → оформление → успех → «Мои заказы».
- [ ] Смена цены и наличия в админке-макете отражается на витрине.
- [ ] Нет белого экрана при отсутствии `window.Telegram`.
- [ ] В `screenshots/` лежат снимки 6–8 ключевых экранов (если получится снять через Playwright/Chromium в вьюпорте 390×844).
- [ ] В репозитории нет секретов (в демо их и быть не должно).

## 11. Чего НЕ делать

- Не добавлять бэкенд, базу, бота на aiogram, авторизацию и реальную отправку заказов.
- Не использовать React и другие фреймворки.
- Не использовать `innerHTML` с пользовательскими данными (только `textContent`).
- Не скачивать внешние картинки и шрифты.
- Не складывать всё в один гигантский файл.
